# N48A bounded repeated source replacement

This increment adds a host-qualified control protocol for exactly two retained
source replacements by the same two owners. It is not an N48B guest runtime,
hardware acceptance, source-free/retype protocol, or unbounded recycling API.
The WB 4K / IPAT1 / AD1 profile and existing eight stable slots per owner remain
unchanged. All source and metadata backing stays retained.

## Stable state and admission

Two separate round/coordinator/adapter records and three source/updater banks
remain at stable addresses. `nsrc_init` reserves exactly one successor after the
first bootstrap and initial adapter construction, before round one starts. It
rejects pairwise ancestor identity and metadata overlap, inconsistent bank
identity/stamp fields, and insufficient minimum two-round control capacity.
Fresh initialization failures do not modify the controller or prior binding.

`nsrc_run` calls the actual `nsrr_run`. Only its sequenced return path publishes
that owner's exact first-round departure. A committed adapter or RELEASED
coordinator alone is insufficient. Both departures and both subsequent complete
physical/reflected owner checkpoints are required before successor binding.
Each owner constructs and audits only its own fresh adapter, including actual
VMCS01/02 EPTP readback through platform primitives. The checkpoint records the
current source-pinned root. Historical completion roots may already be evicted.

The common short metadata lock publishes both replacement pointers and the
active generation together. No platform callback is invoked under that lock.
The new coordinator inherits final command and transaction nonce high-water
marks. It never calls the original fresh initializer again. Old coordinator,
tickets, commands, receipts, slots, source pins, traces and completion history
are not reset. Current catalog root pins are valid at handoff and are released
only by the second round's real retirement.

Every outer admission calls `nsrc_before_entry` with its captured generation
before ordinary owner config/registry reads. Old `tsr_released` is historical
completion, not entry authority. Old round failure callbacks are fenced before
abort or global fault. A real in-flight transition failure selects the current
generation and latches fault in the same lock critical section as successor
publication, then propagates retain-stop outside the lock.

The low-level `*_locked` functions are internal typed-controller operations,
not independent public authority based on caller-supplied booleans. Callers
supply valid, stable, exclusive objects separate from pool/source backing.
Range checks reject metadata aliasing; they do not prove ownership of arbitrary
pointers or physical pages. Physical current-CPU and reference observations
occur outside the lock and are release/acquire-published by parked owners.

## Capacity

Initial preflight reserves a minimum two-round control envelope, not arbitrary
future guest key activity. Each round still rechecks the original bounded
capacity predicates. Intervening key switches consume the same unrecycled
slots, trace storage and counter high-water marks. The host fixture uses four
of eight slots per owner without intervening eviction, or six of eight with
two switches that retire the old completion root. No array or counter is reset.
N48B must derive its own concrete guest schedule and capacity before use.

## Host proof and commands

`python3 efi/tests/nested48a_core.py --sanitizer none`
`python3 efi/tests/nested48a_core.py --sanitizer address,undefined`
`python3 efi/tests/nested48a_core.py --sanitizer thread`

The fixture uses production catalog/updater, typed bridge/provider/lease,
registry/private pool, owner reference adapter, dispatch, round/controller and
`nsrm_prepare` / `nsrm_apply`. Two distinct real management plans perform
P→Q→P. The same physical DATA allocations retain their original lifetimes.
Each plan takes its own stopped-cut graph snapshot. The target CAS clears its
A/D bits; all non-target source words, including A/D, retain that round's exact
snapshot. Returning P does not revive either ancestor bank or token.

Tests include both-owner threaded success, historical-root eviction, actual
post-return departure ordering, three-bank overlap and field mismatch,
current checkpoint and second-restore failure retention, minimum-capacity and
high-water rejection, and same actual permit/session/updater addresses across
three generations with stale ancestor ticket/typed-token/trace rejection.
VMX and invalidation primitives are injected: these are host protocol and
real memory-plan/CAS tests, not physical instruction evidence.

`python3 efi/tests/nested48a_freestanding.py` builds a fresh complete retained-WB
kernel closure, explicitly compiles and links the new chain object and checks
its production symbols plus the new include dependency. It is a link-only
N48A proof. It does not select an N48 guest payload, build an N48 ESP, boot a VM,
or establish runtime reachability. Use the existing cloud environment script
with an available official GNU-EFI dependency prefix.

No previous N47 or N41 result is relabeled as fresh N48 acceptance. Independent
review, directed publication scheduling and affected-source regressions must
be recorded against the exact frozen source separately. N48B runtime and
hardware qualification remain separate work.
