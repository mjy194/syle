# N46A fixed dedicated UC atomic integration

This is a software-only opt-in for one immutable, dedicated 4 KiB UC data page
with IPAT1/AD1. Source tables, EPTP walks and all other backing remain WB. It is
not the earlier AD0 WB-to-UC transition, physical UC provisioning, live retyping,
guest structural updates, large-page UC, or backing reclamation.

`nrc_init_atomic_uc` binds one target GPA, one target HPA and a nonzero immutable
type epoch. The target must be a one-page nonexecuting DATA span with only UC in
its allowed-type set. Other data and every TABLE must be WB. Overlapping or
foreign target addresses, mixed masks, IPAT0 and unsupported source classes are
rejected. The authority must supply the exact owned lifetime, permissions and
current memory type. Neither a pointer nor registration proves a physical alias
or cache audit. The eventual runtime must establish that proof before publication.

`nested_ept_atomic_walk_uc_ipat` separately permits UC or WB 4 KiB leaves and
checks source type against typed backing before any A/D update. UC execute
permission is rejected. No Intel effective-type matrix is guessed: this bounded
contract requires identical source/authorized backing type with IPAT1 and a WB
EPTP. Guest PAT is ignored for the data access. UC applies to the data page, not
to the atomic source-table words, which remain WB.

Fresh NAC permits and durable traces save the fixed UC target and type epoch.
Every guard rechecks that policy, and promotion revalidates full source/cache/A-D
identity and typed backing. The typed owner additionally binds catalog policy and
epoch to the lease/directory and the exact dedicated target HPA. Separate lease,
registry and sparse constructors preserve old WB-only API behavior.

Stopped-owner TAM now validates each present 4 KiB leaf's source type against its
backing, including registered source roots that are not active on either owner.
It preserves the type epoch while advancing the A/D epoch and cache generation.
The prior owner closure, source pins, updater drain, reference removal, exact
owner receipts, invalidation, private trace revocation and reset remain mandatory.
Each owner's first write is independently trapped even after a peer sets shared D.
All target/source backing stays retained after teardown. Atomic lease transition
and backing-release APIs still reject this mode.

Focused checks:

- `python3 efi/tests/nested46a_core.py --sanitizer none`
- `python3 efi/tests/nested46a_core.py --sanitizer address,undefined`
- `python3 efi/tests/nested46a_core.py --sanitizer thread`
- Source `efi/scripts/cloud-env.sh`, then run
  `python3 efi/tests/nested46a_freestanding.py`.

The core test uses actual production catalog, typed owner, sparse cache and TAM
with owned synthetic pages and mocked CPU/cache operations. Its 61 cases cover
mixed UC/WB paths, two owner reset/retrack rounds, independent private first-write
tracking, exact identity failures, full-graph type mismatches, invalid receipts,
unsupported formats and constructor failures. TSan here checks this host test;
it does not claim that these sequential cases exercised a concurrent schedule.
The freestanding gate freshly builds the existing WB N45 image and verifies the
new core symbols, actual O1 freestanding flags, no libc/undefined symbols and
ELF-to-ESP identity. It does not build or execute a UC guest profile.

N46B physical provisioning and actual guest evidence remain separate work.
