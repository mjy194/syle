# N46B fixed UC AD1 physical integration

This is an opt-in development candidate, not a hardware acceptance report.
N46A's independently reviewed software checkpoint is preserved separately.
The new target is `smp-nested-atomic-uc`.

## Boundaries

One dedicated allocator-owned data page at L1 GPA `0xf000` is converted from
WB to UC before publishing an immutable AD1 source catalog. EPT12 sources A/B
map that target UC; source C maps the separate WB alternate. All source and
private page tables, code and other backing remain WB. Every admitted leaf is
4 KiB/IPAT1. The fixed physical EPT roots remain AD0; the composed private roots
are AD1. No PAT/MTRR register write, live retype, mutable source mapping,
non-WB huge leaf, DMA, other-VM consumer or backing reclamation is supported.

The catalog/lease policy may be bound while unpublished. No token, source
session or guest is admitted until physical provisioning commits. The fixed
type epoch stays 1 while A/D reset/retrack epochs advance 1, 2, 3. A/D CAS writes
and reset clears are the only post-publication source-word changes.

## Provisioning and lifetime

`nested_atomic_memory_uc_stage` validates the old complete owned WB fixture,
binds the unpublished metadata, then marks the backing irrevocably retained.
The BSP preallocates and audits all distinct VMXON/VMCS/private-pool pages as WB
and nonoverlapping with the source/data inventory.

Both CPUs enter VMX root without entering any guest or loading a guest VMCS.
Each proves its own PAT, CR3, cache state, initial MTRR-WB classification and
complete unique RW/NX host mapping. Existing PAT0 WB and PAT3 UC are required,
and every PAT entry is checked for legality. The two snapshots must agree.

A one-shot controller requires 40 exact completion receipts:

1. Retained/unpublished ownership, then both owners' preflight audits.
2. Detach the target from all five fixed physical roots: the original backing
   root, both EPT01 roots, and both prebuilt EPT02 parking roots.
3. Actual owner-local INVEPT for every fixed EPTP on both CPUs, ten receipts.
4. Break the single audited host PTE. Both CPUs execute INVLPG, then WBINVD.
   No data access or all-pages-WB target audit occurs in this absent interval.
5. Make the same PTE UC using existing PAT3. Both CPUs execute INVLPG, then
   WBINVD again, followed by complete current-UC host audits.
6. Install final UC fixed aliases and final source words while unpublished.
7. Another actual INVEPT for all five EPTPs on both CPUs, ten receipts, followed
   by each owner's complete final host/fixed-root/private-pool audit.
8. Publish the catalog once. Only after controller commitment does the separate
   guest-admission flag open. Private AD1 root creation/initial INVEPT happens
   later and is not used as evidence for the fixed-root conversions.

A receipt is emitted only after the trusted owner adapter validates the retained
plan, actual objects, current VMX owner and no-entry state and completes the
requested operation. Request/response storage is serialized with release/acquire
mailbox publication. A failure or timeout permanently poisons entry and retains
all allocations. In particular, a failed final guard may occur after catalog
publication: that is an uncertain publication, never a rollback or permission
to retry. The independent admission flag stays closed and the fault latch stays
set even if a later host probe would succeed.

Both VMCS01 and VMCS02 admission enforce CR0.CD/NW masks, clear CD/NW state and
all-MSR interception. Every source/owner admission rechecks current owner host
UC policy. Guest PAT is irrelevant to these IPAT1 mappings. Teardown proves
VMCS clear, private-root retirement, VMXOFF and AP park but deliberately leaves
the UC host mapping and all source/data backing retained. No reverse conversion
or return of UC memory to the allocator is claimed.

## Software evidence and remaining gates

Focused entry points (source `efi/scripts/cloud-env.sh` first):

- `python3 efi/tests/nested46a_core.py --sanitizer none` (61 cases).
- `python3 efi/tests/nested46a_independent.py` (imported independent assertions,
  three build modes and 24 assertion-killed mutants).
- `python3 efi/tests/nested46b_memory.py --sanitizer none` (20 actual staged
  adapter cases; ASan/UBSan and TSan modes are also supported).
- `python3 efi/tests/nested46b_provision.py` (1,217 injectable controller cases).
- `python3 efi/tests/nested46b_runtime.py` (actual bootstrap/pthread mailbox
  with injected privileged primitives and production host-table audit).
- `python3 efi/tests/nested46b_independent.py` (independent adapter/controller
  assertions, three modes and 19 compiled assertion-killed mutants).
- `python3 efi/tests/nested46b_integration.py` (preprocessed guest/owner wiring).
- `python3 efi/tests/nested46b_freestanding.py` (fresh isolated O1 compile/link,
  source hashes, UC/provision/cache symbols, no undefined symbols and exact
  ELF/ESP equality; does not execute a guest).

The actual-guest profile reuses the bounded two-owner 13-checkpoint schedule,
including independent dirty promotions, private-cache eviction, two complete
A/D resets and terminal retirement. Expected serial evidence uses `N46B_` and
`SMP.N46B_PASS` and distinguishes 20 fixed-root bootstrap INVEPT receipts from
later private-root initial/reset/retire invalidations. A passing compile or
mock test is not physical UC evidence. Independent runtime review, a fresh
complete regression and exact-image two-CPU guest acceptance remain separate,
parent-coordinated gates.

`bash efi/tests/nested46.sh --host` combines these focused software gates.
`--runtime` is only a TCG capability-skip check, never a KVM hardware gate.

## Independent runtime review

The bounded production runtime passed independent source and software review.
The frozen v2 snapshot and review archive remain separate immutable evidence.
No production change was needed after that review. The active reproducible gate
`python3 efi/tests/nested46b_runtime_independent.py` imports the exact independent
assertions and privileged-read/instruction substitutions. It runs 100 cache and
physical-entry predicate cases plus seven real-dispatch failure cases alongside
the supplied 286 runtime cases in plain, ASan/UBSan and TSan modes, followed by
27 compiled assertion-killed mutants.

The seven additional cases specifically cover guard failures after successful
catalog publication in the adapter's final readiness, BSP readiness and BSP
final inventory, with the dispatch metadata lock both free and held. They show
that restored UC probing cannot reopen the permanent failure latch. The supplied
fixture's earlier catalog-fault injection is a different prepublication failure
and is not counted as this post-publication witness.

The fresh build runner excludes precisely an input repository-root
`source-sha256.json` receipt before generating its own source manifest. This
avoids a manifest filename collision when running from a frozen candidate;
every copied source remains hashed and checked unchanged. Snapshot receipt
verification remains a separate acceptance step.
