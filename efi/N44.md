# N44 immutable atomic 2 MiB source leaves

N44 is an additive opt-in for EPT12 2 MiB leaves composed into private 4 KiB
EPT02 leaves. N43's four-level 4 KiB profile and APIs remain selectable.
This milestone does not add dynamic source updates, source replacement,
reclamation, 1 GiB leaves, memory-type transitions or guest structural writes.
Hardware execution acceptance remains a separate exact-image gate.

## Source and capability policy

`nested_ept_atomic_walk_wb_ipat_2m` and `nrc_init_atomic_wb_2m` explicitly opt
into WB/IPAT1/AD1 PDE leaves. The old constructors and walker entry points
continue to reject PS. The opt-in decoder accepts PS only at depth 2, requires
bits 20:12 of a 2 MiB base to be zero, and checks physical width, memory type,
IPAT, read permission and all supported fields. PML4/PDPTE/PT PS and 1 GiB
leaves remain unsupported. Nonpresent words ignore their other payload bits.
Unsupported or malformed source format never synthesizes reason 49.

Only the N44 guest profile advertises virtual EPT 2 MiB capability bit 16.
Bit 17 (1 GiB) remains absent. No physical 2 MiB EPT capability is needed:
EPT02 still contains only 4 KiB leaves. Physical EPT A/D and invalidation
requirements remain the same as N43.

The monitor must prove all source-table aliases guest-read-only, writable
pinned WB host authority for its own atomic accesses, and retained identity
and storage through every source lease and private-cache lifetime. Every
shared word access remains atomic. Adding a large source leaf does not weaken
this contract. Detection of structural corruption rejects/poisons and retains
resources; it is not a supported racing structural-update protocol.

## Translation, traces and A/D

The walk terminates at a 2 MiB PDE, then adds the selected 4 KiB subpage offset
before consulting L0 backing authority. Each selected page can have a distinct
HPA or permissions, and other offsets can be unbacked. No contiguous physical
backing or whole-2-MiB permission guarantee is inferred.

A durable trace records each source entry's depth, leaf size, entry GPA,
table HPA, pointer, raw structural word and full source/cache/A-D identities.
A fresh permit revalidates the exact path before promotion, including whether
its terminal is a 2 MiB PDE or a 4 KiB PTE. A forged short/nonleaf trace or a
forged four-entry huge leaf cannot authorize a write.

A shared huge leaf receives A/D through compare-and-swap preserving all
structural fields. Reads never replay an earlier D observation. Every newly
read-filled writable private 4 KiB mapping remains read-only until its own
first write, even if another offset or owner has already set the shared D.
Allowed writes add D at the actual terminal; legal L1 denial adds A only.
L0 backing failure takes precedence over present-path L1 permission denial.

## Stopped-owner maintenance

TAM traverses every registered source root and assigns exact depths to every
registered source-table page. Its graph decoder terminates at a huge leaf and
clears both A and D there, rather than descending to a fictitious PT or treating
D as structural. Nonpresent payload remains unchanged. Every registered table
must still be reached at a consistent depth.

A huge leaf's A/D clear needs only its retained source-table authority. It
does not resolve all 512 backing pages. Backing validation remains per selected
4 KiB fault. Complete owner inventory, physical reference removal, updater
drain, generation-bound invalidation receipts, private-root reset, source
identity audit and final stopped-owner checks remain required before reentry.

Permission downgrades and unmaps in the focused tests are either immutable
alternative roots built before publication or explicit corruption that must
fail closed. They are not live mutable-source support. Dynamic updates would
need a separate stopped-domain source-generation/publication and retirement
protocol; N44 does not depend on or implement that protocol.

## Bounded guest profile

`make -C efi smp-nested-atomic-largepage` selects a separate N44 image. It
retains the low 4 KiB source subtree for code, guest paging and source aliases.
A/B share a high 2 MiB leaf; C uses a 4 KiB alternate mapping. The guest uses
two distinct backed 4 KiB offsets, with explicit private W/D and durable trace
checks across both reset rounds. See [profile details](tests/N44_PROFILE.md).
The profile does not execute malformed/backing-hole/downgrade tests in hardware;
those are software-only cases.

## Focused software checks

From the repository root, source `efi/scripts/cloud-env.sh` before builds.

- `efi/tests/nested44.sh --host`: complete focused gate below, including a
  fresh freestanding build and the mandatory independent mutation gate.
- `efi/tests/nested44.sh --runtime`: two-vCPU TCG CPUID_VMX0 capability skip
  only; requires exit 33 and rejects N44 pass/checkpoint or panic output.
- `python3 efi/tests/nested44_core.py --sanitizer none`
- `python3 efi/tests/nested44_core.py --sanitizer address,undefined`
- `python3 efi/tests/nested44_core.py --sanitizer thread`

These use fresh source copies and production walker/catalog/typed-owner/TAM
code. Physical allocation/CPU/INVEPT operations are mocks. Coverage includes
noncontiguous subpages, a 2 MiB boundary, a read-only backing page, holes,
independent private first-write traps, immutable downgrade/unmap roots,
large-leaf clear/retrack, durable-trace corruption and retained failure paths.
ThreadSanitizer on this fixture is a software check, not physical concurrency
evidence. The independent review gate separately supplies deterministic
concurrent CAS tests and mutation checks.

`nested44_memory.py` adds constructor/all-alias ownership checks and real
production owner fault processing with mocked physical primitives. The
independent gate runs 13 groups in O2/Werror, ASan/UBSan and TSan, including
all 512 nonlinear-backed subpage offsets, 80 barrier-forced shared-PDE CAS
collisions per mode, mixed-depth two-round TAM and 21 weakening mutants.

The real-guest profile, its exact image, software regression and hardware
acceptance are tracked separately. A compile, host test or TCG VMX capability
skip is not evidence that the nested guest ran.
