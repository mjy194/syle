# N43 bounded two-round diagnostic

N43 is an additive successor to N42B. `make smp-nested-atomic-multiround`
selects `VMX_NESTED_ATOMIC_MULTIROUND_TEST`, including N42B infrastructure
flags but isolated `k-nested43-*` objects and separate payload/runtime files.
The accepted N42B target and one-round payload remain selectable unchanged.

This diagnostic covers exactly two physical owners, immutable 4-KiB
WB/IPAT1/AD1 source trees, budget-two private caches and two stopped-owner
A/D resets. It does not establish arbitrary iteration, reclamation, migration,
structural mutations, large-page maintenance or memory-type transitions.

## Execution and evidence

Phases 0–7 retain N42B's A/B/A/A/B/A/B/B and A/B/C/C/B/B/C/B sequence.
The first reset occurs after phase 2, active A/C. Phase 7 performs reset two
with both B active. Phases 8–12 select A/B/A/B/B and C/B/B/C/B. Each owner
executes 13 symbol-checked VMCALL checkpoints; reason-48 retries retain RIP.
There is a bounded 2048-step physical exit loop, without fixed RIP overrides.

Initial writes at 0x40, first-round writes at 0x140 and second-round writes at
0x240 have disjoint owner/key slots. Guest readback verifies actual stores;
post-second-reset guest reads verify both older cohorts. Stopped-host snapshots
also preserve both older cohorts through the final checkpoint and teardown.

The outer checkpoint release follows successful `namr_round`, both matching
completion tags, `NOAM_COMMITTED`, and absent redundant pending markers.
Four source references stay live at every stopped checkpoint after phase 2.
Only terminal teardown drains them. Neither vCPUs, VMCS objects, roots, launch
state nor trace allocation is reinitialized between rounds.

Full TAM snapshots for both rounds retain ticket, source-page raw words,
roots, receipts and changed-CAS totals before the next round overwrites TAM.
Changed-CAS expectation is independently counted from each round's stopped
snapshot. Receipt output includes nonce/stamp, exact identity, HPA/EPTP,
owner/history/ack and old/new generations. Cross-round checks preserve all
four root identities, EPTPs, bindings, source identities and allocation
lifetimes. Nonces/domain epochs increase, private generations advance twice,
and outer epochs are 1 → 2 → 3.

Expected totals: eight exact reset receipts, eight post-reset target
promotions, thirteen target promotions overall, five creations, one eviction,
five terminal retirement receipts. Final promotion vectors are (3,3,0) and
(1,3,3). `N43_CHECKPOINT_TRACE_USED`, `N43_TRACE_USED` and `N43_TRACE_TOTAL`
report actual used trace records. The capacity stays 256 per owner; records
are not recycled and checkpoint counts must never decrease. `SMP.N43_PASS`
is emitted only after the final checks and retained-source teardown checks.

## Focused validation

Source `scripts/cloud-env.sh` in the current cloud workspace before building.
From the repository root:

- `python3 efi/tests/nested43_integration.py`: actual preprocessed wiring,
  checkpoint sequence, exact receipt checks, completion gate and payload.
- `python3 efi/tests/nested43_freestanding.py`: unique fresh source copy,
  real Makefile build, object/ELF undefined-symbol checks, kernel/ESP equality.
- `efi/tests/nested43.sh --host`: production fixture under plain, ASan/UBSan
  and TSan; independent review gate; structural and freestanding checks.
- `efi/tests/nested43.sh --runtime`: two-vCPU TCG only, requiring exit 33 and
  exact `SMP.N20_BLOCKED CPUID_VMX0`, rejecting N43 checkpoint/pass or panic.

Each runner records a new unique evidence directory. A TCG capability skip
is not VMX acceptance. Independent review, final-source full regression and
separately authorized exact-image nested-KVM runs at both requested memory
sizes remain distinct gates. Do not freeze or label this profile accepted
based only on a host test, compile, structural check or TCG skip.

The host fixture's trace-exhaustion stress is a separate software-only test:
initial filling plus three clears consume the actual 256-record allocation,
using the same 96-page owner pool and 64 cached leaves per generation. It
invokes production fault processing but does not execute guest instructions.
Its third clear is not part of the two-round physical diagnostic or evidence
of physical execution beyond two rounds.
